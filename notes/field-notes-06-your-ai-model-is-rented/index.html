Field Notes #06: Your AI model is rented

Hosted AI models get retired, sometimes on a few weeks' notice. How to plan the move-out before the notice arrives: config, a tested fallback, and a rehearsal.

Field Notes is a series of short, plain-language explainers on how software is built. Each one starts with a picture and ends with a rule you can use.

Hosted models get retired

Same prompt. Same code. One day the model behind it is gone. You don’t own it. You rent it.

It happened to me

One of my parsers ran on a hosted model, and the provider gave about six weeks’ notice. I moved it, and made the model a setting. The next move is a config change, not a code change.

Model in config, not in code

Buried in code, a move means a code change, a review and a release. As a setting, it’s one line.

Keep a spare room

When the main model is down or slow, a fallback keeps the feature up. Test it too: a spare key you’ve never tried isn’t a spare key.

Rehearse the move

A new model isn’t a drop-in. Same prompt, different habits: format, strictness, what it refuses. Keep a small set of real inputs with known right answers, and run it on the new model before you switch. Engineers call all of this avoiding lock-in.

The rule

Plan the move-out before the notice.
