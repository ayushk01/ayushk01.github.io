Field Notes #07: Check the AI's note against the record

I built fhir-notecheck, an open-source harness that checks AI-written clinical notes against the patient's FHIR record and scores the checker itself on 240 planted errors.

Field Notes is a series of short, plain-language explainers on how software is built. This one is about my own open-source project, fhir-notecheck.

AI scribes invent and drop

AI scribes now draft clinical notes. The mistakes that matter: inventing things (a drug the patient isn’t on, a diagnosis nobody made) and dropping things (an allergy). If the record is in FHIR, a note can be checked claim by claim.

I planted 240 errors

290 notes for 50 synthetic Synthea patients: 50 correct, 240 with one known error each. The error goes into the facts before the note is written, so every label is exact.

The result

An LLM extractor caught 239 of 240, with no false flags on the 50 correct notes. Its one miss: it dropped “human” from “insulin isophane, human”, so the dose check found no matching drug.

The catch

A free, deterministic rules checker caught 90%, but its false flags on correct notes rose from 4% to 14% once an LLM wrote the notes. Read every catch rate next to the false-flag rate: a checker that flags everything catches 100%.

My favourite bug

A fentanyl patch’s “72 hour” was read as a heart rate of 72. Others: a bold Allergies: header that wasn’t seen as a header, and “Prediabetes (finding)” dropped because my filter kept only disorders.

The real run

The takeaway

Planted errors are large: treat 100% as “the easy cases”, not real-world accuracy. Synthetic patients only. Code, data and every model reply are in the repo, and the whole LLM run cost about $0.53.
