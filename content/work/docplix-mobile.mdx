## The product

DocPlix ships two mobile apps off a shared React Native codebase:

- **Patient app** — for patients to book appointments, see prescriptions, and message their clinic.
- **Clinician app** — for clinicians on the go: today's appointments, quick patient history, brief notes between consults.

Both share the bulk of their data layer and types with the web app. The split happens at the navigation and feature-flag boundary, not at the API layer.

Across both apps:

- Navigation architecture (React Navigation + typed routes).

- Push notifications: APNs + FCM via a single backend service.
- Release engineering: CI builds, code signing, TestFlight + internal Android tracks, production releases.

## A few hard things

**Sharing code with the web app without becoming a monorepo monster.** The temptation with React + React Native is to share *all* the React. The right line, for us, was sharing the types and the data layer (React Query + the typed REST client) but *not* the components. UI primitives diverge too much between web and native to share cleanly. Pretending otherwise meant `<View as="div">` ergonomics that nobody actually liked.

**Hermes bytecode cache.** Spent a few days on a bug where one specific screen would crash on Android with no useful stack trace. Turned out to be Hermes' bytecode cache holding onto a stale module after a dependency upgrade. The lesson — when Android RN crashes are inexplicable and the JS stack is empty, check Hermes first.

**Offline support, in the limited form we needed it.** Doctors lose signal in clinic basements. The right answer wasn't a full offline-first architecture (that's a multi-quarter rewrite) — it was caching the day's appointments and the patient list on app open, queueing writes locally, and surfacing a small "syncing" indicator. 80% of the value for 5% of the effort.

**Release cadence.** Two-week sprints, weekly TestFlight + internal Android builds, biweekly production releases. The discipline that made this work wasn't the cadence — it was making the build process boring. Once `pnpm release` did everything from version-bumping to store upload, releases stopped being a thing anyone dreaded.

## Stack

- **App:** React Native, TypeScript, React Navigation, Reanimated, Zustand for local state, React Query for remote.
- **Engine:** Hermes on both platforms.
- **Push:** APNs + FCM via a single backend service.
- **CI / releases:** GitHub Actions for builds, Fastlane for signing and store uploads.
