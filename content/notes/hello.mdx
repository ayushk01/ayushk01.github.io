---
title: "Why I keep coming back to React Query"
blurb: "It's not the caching. It's the way it makes the absence of a cache visible."
date: "2026-05-02"
---

I've used React Query, SWR, RTK Query, and a handful of bespoke fetch wrappers. I keep coming back to React Query and I think I finally know why.

It's not the caching. The caching is fine. Plenty of libraries cache.

What React Query does that nothing else I've used does as cleanly is **make the four states of a request — fresh, stale, loading, error — first-class.** Every screen I've ever built has all four. The bug-prone code is the code that pretends one of them doesn't exist. ("Oh, we don't worry about stale data here." Three months later: a UI that shows you yesterday's appointment list because the cache invalidation rule had a typo.)

React Query forces you to name the four states by default. That's the whole feature. The fact that the cache exists is a happy side effect.

The corollary: if I'm reaching for `useEffect(() => { fetch(...) })` on a project, I'm almost always making a mistake. Not because `useEffect` is bad. Because the four states aren't visible at the call site.
